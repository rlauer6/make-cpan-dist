# Release Notes — CPAN::Maker 2.0.6

**Released:** Thu Jul 23 2026  
**Author:** Rob Lauer &lt;rclauer@gmail.com&gt;

---

## Overview

Version 2.0.6 is a significant internal refactoring release. The
primary theme is the elimination of a legacy `%args` hash that was
used to shuttle option values between parsing and application phases —
a holdover from the original Bash script era. All option values are
now applied directly via `CLI::Simple` setter methods. This release
also adds first-class support for `suggests` dependencies (alongside
the existing `recommends` support), exposes a `license` field in both
the buildspec schema and the generated `Makefile.PL`, and overhauls
the build system's dependency scanning and syntax-checking pipeline.

---

## New Features

### `suggests` Dependency Tier

A new `suggests` dependency tier is now fully supported end-to-end:

- New `--suggests` command-line option for `cpan-maker`.
- New `suggests` file generated by `CPAN::Maker::Bootstrapper`.
- `suggests` entries are written into the `META_MERGE`
  `prereqs.runtime.suggests` section of the generated `Makefile.PL`.
- `buildspec.yml` `dependencies.suggests` key is now recognised and validated.
- The `buildspec-schema.json` schema has been updated to include the
  `suggests` field under `dependencies`.

### `license` Field

- A top-level `license` field is now supported in `buildspec.yml`.
- The `--license` command-line option has been added to `cpan-maker`.
- The generated `Makefile.PL` now honours this value (previously
  hardcoded to `'perl'`). Default remains `perl`.
- `buildspec-schema.json` updated to include the `license` property.

### `write-makefile` Enforcement

- `cmd_makefile` now enforces that the `--requires` file actually
  exists on disk, not merely that the option was supplied. A clear
  error message is emitted if the file is absent.

### `cmd_build` Dry-Run Output

- In dry-run mode, `cmd_build` now prints a structured dump of all
  resolved dependency artifacts (`requires`, `recommends`, `suggests`,
  `test_requires`, `build_requires`) rather than the raw internal
  `%args` hash.

### `install` Convenience Target

- `project.mk` now provides an `install` phony target that installs
  the built tarball into `$HOME` using `cpanm`.

### `package` Convenience Target

- A new `package` phony target in the `Makefile` runs a clean build
  with `LINT=on SCAN=on`.

## Dependency Scanning Overhaul

The dependency scanning pipeline has been substantially rewritten:

- A single grouped Make rule (`requires.raw recommends.raw
  suggests.raw &:`) now invokes `scandeps-static` once, producing all
  three runtime dependency tiers in a single pass using `--raw`,
  `--requires-file`, `--recommends-file`, and `--suggests-file` flags.
- A separate `test-requires.raw` rule scans `t/` independently.
- A generic `%: %.raw` pattern rule reconciles fresh scan output
  against history (skip list and previous run) via `cmb filter`,
  replacing the inline Perl `filter_requires` script that was
  previously embedded in the `Makefile`.
- The `Makefile` now tracks `recommends` and `suggests` as explicit
  build dependencies alongside `requires`.
- `scandeps-static.pl` → `scandeps-static` (command name updated).
- `md-utils.pl` → `markdown-render` (command name updated).
- `*.raw` files are now excluded from version control (`.gitignore`) and cleaned by `make clean`.

## Build System — `perl.mk` Refactoring

### Syntax Checking Merged Into Template Rules

The separate `%.pm.checked` / `%.pl.checked` sentinel targets and the
two-phase `check-syntax` barrier have been removed. Syntax checking is
now bundled directly into the `%.pm` and `%.pl` pattern rules:

- `deps.mk` now depends on `.pm.in` / `.pl.in` source files rather
  than the built `.pm` / `.pl` targets. This eliminates the
  chicken-and-egg problem that previously required the two-phase
  approach.
- `make clean` can no longer trigger a spurious rebuild through the
  `deps.mk` include.
- The `deps.mk` include is now unconditional (the `ifeq ($(filter
  clean distclean,...)` guard has been removed).
- `.PRECIOUS: %.pm %.pl` declarations removed (no longer needed).
- `CLEANFILES` no longer includes `*.pm.checked` / `*.pl.checked` entries.
- `check-syntax` is retained as a convenience alias that simply
  depends on `$(PERL_MODULES)` and `$(PERL_BIN_FILES)`.

### `perlcritic` Improvements

- Two new variables `PERLCRITIC_SEVERITY` (default: `5`) and
  `PERLCRITIC_THEME` (default: `pbp`) are now configurable.
- `perlcritic` output is now captured with `tee` so it is both
  displayed and stored in the `.crit` sentinel file.
- `set -eo pipefail` ensures pipeline failures are correctly propagated.

### Bug Fixes in `check_syntax_pm` / `check_syntax_pl`

- References to `$<` (prerequisite) corrected to `$@` (target)
  throughout the syntax-checking snippets, fixing cases where the
  wrong filename was used for skip-list matching, module name
  derivation, and pod checking.
- Redundant `local_cleanfiles` initialisation and duplicate `trap`
  lines removed from the `check_syntax_pm` and `check_syntax_pl`
  snippets (the outer rule already sets the trap).

### `critic` Target Fix

- The `critic` convenience target now invokes `$(MAKE) check-syntax …`
  rather than bare `$(MAKE) …`, and the `test -n` guard around
  `PERL_SCRIPTS` is now a proper `if` block.

### `update.mk` — `.gitignore` Synchronisation

- `post-update` now merges missing entries from the bootstrapper's
  canonical `gitignore` into the project's `.gitignore` using `comm
  -13`.

### `release-notes.mk`

- The `release-notes` target now calls `cmb release-notes` instead of `bootstrapper release-notes`.

## Internal Refactoring — `CPAN::Maker`

### Removal of Legacy `%args` Hash

The `%args` hash that was threaded through `parse_buildspec` and all
its callees (`parse_project`, `parse_pm_module`,
`parse_include_version`, `parse_dependencies`, `parse_path`,
`write_resources`, `write_pl_files`, `write_provides`,
`write_extra_files`) as a carrier for parsed options has been removed
entirely. Each method now calls the appropriate `CLI::Simple` setter
directly:

| Former `%args` key | Replaced by setter |
|---|---|
| `$args{m}` | `set_module()` |
| `$args{a}` | `set_author()` |
| `$args{d}` | `set_abstract()` |
| `$args{D}` | `set_requires()` |
| `$args{T}` | `set_test_requires()` |
| `$args{B}` | `set_build_requires()` |
| `$args{Y}` | `set_recommends()` |
| `$args{M}` | `set_min_perl_version()` |
| `$args{V}` | `set_version_from()` |
| `$args{e}` | `set_exe_files()` |
| `$args{t}` | `set_tests_path()` |
| `$args{S}` | `set_scripts_path()` |
| `$args{F}` | `set_postamble()` |
| `$args{R}` | `set_recurse()` |
| `$args{y}` | `set_pl_files()` |
| `$args{c}` | `set_core_modules()` |

### `_apply_buildspec_args` Removed

The `_apply_buildspec_args` method, which mapped single-letter `%args`
keys back to object attributes, has been removed as it is now
redundant.

### `parse_buildspec` Return Value

`parse_buildspec` now returns nothing (`return;`) instead of a `%args`
hash. All callers updated accordingly.

### `write_makefile` — `suggests` and `license`

- `write_makefile` now reads and applies `get_suggests()`, emitting
  `suggests` entries into the `prereqs.runtime` section of
  `META_MERGE` alongside `recommends`.
- `$LICENSE` is now read from `get_license()` (defaulting to `'perl'`)
  and substituted into the generated `Makefile.PL`.
- Author parsing uses the `choose {}` idiom with a documented fallback
  (`Anonymouse <anonymouse@example.org>`).
- `MODULE_ABSTRACT` falls back to `$PM_MODULE` if not set.
- The `exe_files` existence check uses `-f` instead of `-s` (a file can be valid but empty).

### `cmd_build` — `stage_distribution` Signature

- `stage_distribution` no longer accepts or passes an `args`
  hashref. The `builddir` parameter is the only positional argument
  consumed from `%params`.

### `JSON::Validator` Tagged as `recommends`

Both call sites that `eval { require JSON::Validator; 1 }` are now
annotated with `## scandeps: recommends`, ensuring the scanner
correctly classifies `JSON::Validator` as a recommended (not required)
dependency.

### `CPAN::Maker::Role::FileUtils`

- `write_extra_files` no longer accepts or returns a `%args` hash.
- `parse_path` now calls setters directly and no longer returns
  `%args`.
- Noted (with inline comments) that `exclude-files`, `extra` output
  path, and `git` project key currently have no corresponding
  `CLI::Simple` accessors and are left unapplied pending future work.

## Documentation Updates

- `--author` option description updated to document the expected
  `'name <email>'` format and default value.
- `--license` option added to the OPTIONS section.
- `--recommends`, `--requires`, and `--suggests` options documented in
  the OPTIONS section.
- `--requires` documented as mandatory for `write-makefile`, with an
  explanation of why (most CPAN installers only install `requires` by
  default).
- `license` field documented in the BUILD SPECIFICATION FORMAT section.
- `suggests` documented in the `dependencies` subsection of the BUILD
  SPECIFICATION FORMAT.
- VERSION string in the POD now uses the `@PACKAGE_VERSION@` template
  token (was previously hardcoded to `2.0.1`).
